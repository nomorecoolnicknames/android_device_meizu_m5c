# M5c — матрица компонентов на 2026-08-27 (редакция 5)

Снята после того, как в аппарат вставили SIM и был собран полный ROM.
Главное отличие от редакции 4: **сотовая связь закрыта целиком** (SIM READY,
регистрация в LTE), **BD-адрес Bluetooth стал заводским**, устранён крашлуп,
уводивший аппарат в перезагрузку по сторожевому таймеру, и — отдельно —
**снят собственный вердикт по разрывам изображения**: контрольное A/B его не
подтвердило, причина снова открыта.

Артефакты:

- ROM: `out/target/product/m5c/lineage-14.1-20260827-UNOFFICIAL-m5c.zip`
  (md5 `931c094395bcabcae86f204cf08ba148`, 520 446 455 байт). Внутри —
  наш boot.img (md5 `bfe36a7137ce996ea83dcc310a20a5b0`) с ядром
  `a374f6ce70fbf90b7537e444c4092983` и ramdisk с автозапуском модема.
- Отдельный boot для ручной прошивки:
  `artifacts/boot_m5c_49_20260827_wlanfix.img`
  (md5 `88ed99c6b7f57b04c50b33f3ba0985f3`).

Проверки ниже сняты с живого устройства (710HVBR923RYK) на системе, где
собранные `telephony-common.jar`, `libhwui.so`, `md_ctrl`, `btaddr_mtk` и
полный `ecc_list.xml` уже стоят.

Статусы: **РАБОТАЕТ** — проверено в рантайме; **ЧАСТИЧНО** — поднимается, но
задачу не выполняет; **СЛОМАНО** — причина известна; **ОТКРЫТО** — причина не
установлена; **N/A** — железа нет.

| Мультиплексор | **РАБОТАЕТ** | `gsm0710muxd`, кадры без потерь |
| Автозапуск цепочки | **РАБОТАЕТ** | `mtk.md1.status=init_done` → mux → RIL, из init, до телефонного процесса |
| Чтение SIM | **РАБОТАЕТ** | `+CPIN: READY`, `+CRSM` отдаёт EF_DIR с USIM AID |
| **Статус SIM во фреймворке** | **РАБОТАЕТ** | `gsm.sim.state = READY,ABSENT` при **штатном** `ecc_list.xml` |
| **Регистрация в сети** | **РАБОТАЕТ** | `beeline`, `25099`, **LTE**, `voice home data home`, ≈ -54 dBm |
| Звонки, SMS, мобильные данные | не проверялись | тракт готов, нужен живой тест |

Причина, стоившая дня: `MtkEccList.updateEmergencyNumbersProperty()` писал в
`ril.ecclist` слитый список аварийных номеров (SIM + весь `ecc_list.xml`),
а значение system property ограничено 91 символом. `SystemProperties.set()`
кидал `IllegalArgumentException` внутри `MT6735.processSolicited()`, и это
исключение съедало **каждый** ответ `GET_SIM_STATUS` — оба слота навсегда
оставались NOT_READY. Лечится обрезкой по границе номера и try/catch.

## 7. Открытые фронты

1. **Разрывы изображения** — причина открыта заново. Следующие шаги из
   `M5C_TEARING_LANE.md`: убедиться глазами, что стежок вообще виден на
   текущей сборке; если да — проверить RDMA-underflow (`maxplanes 1`) и
   снять WDMA-захват выхода OVL, сверив с поданным буфером.
2. **GPS — фикс позиции.** В работе.
3. **Фронтальная камера** — программная сторона исчерпана, проверять
   заменой модуля.
4. **Звонки, SMS, мобильные данные** — тракт готов, нужен живой тест.
5. **FM** — не проверялось.

## 8. Инфраструктурные заметки

- Сборка ROM: `lunch lineage_m5c-userdebug && mka bacon` с
  `JAVA_HOME=/usr/lib/jvm/temurin-8-jdk-amd64` (по умолчанию в системе JDK 17,
  на нём Soong падает). Полная сборка с нуля — около 41 минуты на 28 потоках,
  инкрементальная — 13-15 минут.
- **Сборочный `boot.img` берёт ядро из `rootdir/kernel`.** Там лежал prebuilt
  от 15 июня; прошивка такого ROM откатила бы всю работу по 4.9. Теперь там
  наш `Image.gz+dtb_stock.dtb`. Проверять после каждой сборки:
  `abootimg -x boot.img && md5sum zImage`.
- Гейт упаковки ручного boot: `strings boot.img | grep -c mt6735m-mmc` == 2 и
  `grep -c 'mediatek,msdc'` == 0. Если правится ramdisk — собирать через
  `pack_rd.sh`, обычный `pack.sh` обновляет только ядро.
- USB-узел телефона на девбоксе появляется как `root:root` (нет udev-правил),
  adb его не видит; хелпер `usbfix.sh` открывает узел по серийнику, номер
  меняется после каждой перезагрузки.
- Подмена `/system/framework/*.jar` на живом устройстве заставляет dex2oat
  пересобрать boot-классы: первые 2-3 минуты после загрузки телефония ещё не
  поднята, пустые `gsm.*` в это время — не регрессия.
- Никогда не писать `/*` или `*/` внутри тела комментария в ядре: дважды
  ломало сборку.
